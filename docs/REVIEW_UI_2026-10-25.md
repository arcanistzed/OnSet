# Review: the OnSet interface, from a DJ's point of view (2026-10-25)

A read of every screen in `ui/src` (Library, Track review, Transitions, Set planner, Show, Settings and the OnSet Live window) against the plan's interface requirements (P5.2 editing and review, V1 desktop keyboard, undo, playback, approval and preview) and against what a DJ preparing a set needs. Findings are ranked by how much they cost a DJ in time, trust or lost work. Each names where it lives, what goes wrong and a proposed fix.

This is a source review. Nothing was built, run or clicked for it (C: had 2.8 GB free and no builds were allowed), so behaviour is read from the code, not observed. The installed build is 3630ea4. None of the fixes below would weaken the rules the plan keeps: the DJ decides, cues are approved one by one or by explicit selection, and every rekordbox write is previewed first.

## 1. Clicking a cue letter on the waveform moves it and un-approves it

**Where:** `main.tsx` Timeline, `onPointerDown`/`onPointerUp` (lines 84–90), and its `onMove` (line 269), which saves `status:'proposed'` with the new position.

**What goes wrong:** pressing on a cue letter starts a drag, and releasing always saves a move to the pointer position, even if the pointer never moved. With Snap to beats on (the default), the position snaps to the nearest beat, which is rarely the cue's exact time. So a single click on an approved cue moves it slightly and resets it to "proposed", and the toast says "Cue moved; approve when ready". A DJ who clicks the letter to hear the cue loses an approval without meaning to.

**Clash with 3630ea4:** that commit made the coloured letter in the cue list play from the exact cue time. The waveform draws the same coloured letter, so the same-looking control plays the cue in one place and moves it in the other.

**Fix:** treat a press and release that moves less than about 4 px as a click. A click on a letter seeks to the cue's exact time and plays, matching the cue list. Only a real drag moves the cue, and only a drag past the threshold resets its approval. While dragging, show a ghost line and the target time, and let Esc cancel the drag. The same threshold applies to section edges.

## 2. Restoring a rekordbox backup is one click

**Where:** `main.tsx` Settings → Data & backups → rekordbox write history (line 447).

**What goes wrong:** **Restore** rewrites rekordbox's database straight away. There is no preview of what changes, no confirmation and no reminder to close rekordbox. Workspace snapshots on the same page already do this properly (`WorkspaceRecovery.tsx`): Preview restore, a table of record counts before and after, a tick box saying what will happen, and a red Restore button.

**Fix:** give rekordbox restores the same pattern. Preview which tracks and cues change, require the tick, and refuse while rekordbox runs, as writes already do.

## 3. Analysis runs on every visible track when none is ticked

**Where:** `main.tsx` selection bar (lines 228–233) and `library.ts` `analysisSelection`.

**What goes wrong:** with no track ticked, **Light analysis** and **Deep analysis** act on every visible track. The label does say "Analyse 160 visible tracks", but one click on Deep analysis queues hours of work and several gigabytes of stems. This happened on 2026-10-22: duplicate 160-track deep jobs had to be cancelled, and the disk filled three times that day.

**Fix:** ask before any job of more than a few tracks. Name the count, a rough time (deep analysis takes about 20 minutes a track here) and the disk it needs. Also offer "Deep analysis of tracks not yet analysed deeply", so a rerun doesn't redo finished work.

## 4. No "next track" flow through the review queue

**Where:** `main.tsx` Track review header (line 266) and Library view **Review queue** (lines 183–185).

**What goes wrong:** the Library ranks tracks by review priority, with disagreements, stale cues and high-impact cues first. But Track review only offers a drop-down of all tracks in library order. After finishing a track, the DJ goes back to the Library, finds the next one and opens it again. The reason a track is in the queue (for example "rekordbox and OnSet disagree on the grid") shows only as a Library subtitle, not on the review page.

**Fix:** add **Previous** and **Next in queue** buttons, with shortcuts such as `[` and `]`, and show the track's queue reasons at the top of Track review. When every cue of a track is decided, offer "Next in queue".

## 5. Writing cues to rekordbox works one track at a time

**Where:** `main.tsx` Cues tab → Write to rekordbox (lines 282–293).

**What goes wrong:** the preview and apply buttons send only the current track, although the service accepts a list (`rekordbox-preview` with `track_ids`). Writing a reviewed crate means opening each track, previewing, closing rekordbox and applying, once per track, with a database backup each time.

**Fix:** add **Write approved cues** to the Library selection bar and to the planner's set card. It previews every ticked track's changes in one list, grouped by track, with the same add, replace and delete tags. One apply follows, with one backup. The per-track button stays.

## 6. Pages share hidden state

**Where:** `main.tsx`: the Transitions **Outgoing** select uses the same `selected` state as Track review (line 314). The planner's track pool is the Library's current filter or ticks (`ids`, line 370).

**What goes wrong:** choosing an outgoing track on Transitions changes which track Track review shows. A search typed in the Library silently narrows the set planner to the matching tracks. The planner says "Plans from N visible library tracks", but not which tracks or why.

**Fix:** give Transitions its own outgoing track, with a **Review this track** link. Give the planner an explicit pool: Whole library, Ticked tracks or a rekordbox playlist, shown with the count and an **Edit** link to the Library with that selection.

## 7. Long track lists are plain drop-downs

**Where:** Track review (line 266), Transitions (314–316), the planner's opening and closing tracks (349–350), Must play and Exclude (`ui.tsx` `TrackPicker`), and Energy calibration (`LocalSettings.tsx`).

**What goes wrong:** each lists all 160 titles unsorted, with no artist, BPM or key and no type-to-search. Two tracks with the same title cannot be told apart.

**Fix:** one shared searchable track picker that filters by title, artist, key or BPM as you type, and shows artist, BPM and Camelot key on each row. It keeps a short list of recent tracks first.

## 8. Raw state words

**Where:** Library columns, cue pills and job pills (`ui.tsx` `Pill`).

**What goes wrong:** "partial" is shown for every deeply analysed track while the Beat This! model was unavailable, though those tracks were fully usable. "pending", "imported", "stale" and "unreviewed" are not explained. The Review column mixes "reviewing" and "stale" states without saying what to do.

**Fix:** use plain labels with a hover note on the cause. For example, "Analysed (1 model missing: Beat This!)", "Needs analysis", "Changed since review: check cues". Keep the raw state in the tooltip for support.

## 9. The Library cannot be sorted

**Where:** `main.tsx` table head (line 238).

**What goes wrong:** there is no way to sort by BPM, key, energy or state, which DJs do constantly. The filters help, but a sorted BPM or key column is the expected first move.

**Fix:** make each column header sort on click, ascending then descending, with the sort remembered. Sort keys by Camelot number so 8A sits next to 8B and 9A.

## 10. Keyboard and accessibility gaps

**Where:** global key handler (`main.tsx` lines 140–144), the waveform canvas (line 82) and the cue list (`CueReview.tsx`).

**What goes wrong:**
- **Space plays only on Track review.** On Transitions and Stems a DJ reaches for the mouse.
- **No keys to move between cues or pages.** You Tab into each cue row; there is no ↑/↓ between cues and no shortcut for the main pages.
- **A and R act on the focused row only.** That's correct for safety, but there is no visible focus style named in the hint, so it isn't obvious which cue a key will approve.
- **The waveform is mouse-only.** Its label points to the cue list, which is right, but section edges have no keyboard equivalent outside the Corrections table.
- **Several controls have no visible label,** only colour: the cue letters, and the energy meter, which has no unit.

**Fix:** add ↑/↓ between cue rows with a clear focus ring, and `Ctrl+1`…`6` for the pages. Make Space play and pause the current audio on every page. Add a keyboard reference behind `?`. Give the focused cue row a visible outline and its role letter in the hint ("A approves cue D").

## 11. ChatGPT in three places

**Where:** Set planner → AI adviser (with a ChatGPT account section inside it), Set planner → its own ChatGPT panel through `chatgptPanel` (lines 378–392), and Settings → ChatGPT. There are two "Look up track details online" tick boxes (`research` in `main.tsx`, `web` in `AiAdviser.tsx`) and two model pickers.

**What goes wrong:** it is unclear which button uses which provider. "Suggest a set" and "Enrich profiles" sit apart from "Compare with the planner" and "Look up track details", though they do similar things.

**Fix:** keep the account and model only in Settings → ChatGPT. Make the AI adviser card the only place to act, with one provider list, one "online" tick box and the four actions together.

## 12. Smaller items

- **Show page:** **Start show** sits below the active tab's settings, so on long tabs (Effects) it's off screen. Pin Start/End show and the screen choice at the top of the page.
- **Jobs:** the list keeps every job ever run, oldest mixed with newest, and offers **Resume** on partial jobs whose missing part cannot succeed (for example while Beat This! is unavailable). Group the list into Active and Finished, collapse finished jobs, and explain what Resume will redo.
- **Busy state:** any request disables most buttons across the app (one global `busy`). Fine for writes, but it blocks reading and playback buttons for no reason during long calls. Limit it to the card that started the request.
- **Track profile:** familiarity is "0–1" while energy is "1–10". Use one 1–10 scale or a named choice (Unknown, Known, Anthem). **Save profile** saves every field at once; show which fields changed.
- **Planner brief:** the energy arc is typed as comma-separated numbers. A small row of 1–10 steppers, or a drag-the-points curve, would show it.
- **Cue review:** a cue's position field accepts any number. Show the bar and beat beside it ("bar 32, beat 1"), as rekordbox users think in bars.
- **Errors:** errors stay until dismissed, which is right. But confirmations disappear after 5 s, including "Approved changes written; backup saved". Keep write confirmations until dismissed, with the backup's name.

## Proposed first fixes

Four changes give most of the benefit with little risk, in this order:

1. **Waveform click versus drag (finding 1).** It stops silent loss of approvals and matches 3630ea4's cue-list behaviour. It touches only the Timeline component and adds a unit test for the threshold.
2. **Confirmations for large analysis jobs and rekordbox restores (findings 2 and 3).** Both reuse the existing preview pattern; rekordbox restore needs a dry-run preview from the service.
3. **Next-in-queue review (finding 4).** Previous and Next buttons with `[` and `]` on Track review, plus the queue reasons at the top of the page.
4. **Batch cue write from the Library selection (finding 5).** It uses the existing multi-track preview and apply, so only the interface changes.

Findings 6 to 12 can follow in any order.
